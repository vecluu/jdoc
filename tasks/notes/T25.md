## Root causes
- **RealMavenResolutionIT, locally**: `findMaven()` only looked at `JDOC_MVN` and the PATH; non-login shells have no
  `mvn` on the PATH.
- **RealMavenResolutionIT, in CI** (reproduced with an empty `-Dmaven.repo.local` temp repo): the IT's temp project
  used the *default* plugin versions of whatever `mvn` ran it. Maven 3.10.0 (runner PATH) binds
  `maven-resources-plugin:3.5.0`, Maven 3.9.16 (`./mvnw`) `maven-compiler-plugin:3.15.0`; the jdoc build pins
  compiler 3.14.1 and (then) used the wrapper's default resources 3.4.0, so the offline probe failed with "has not been
  downloaded before". Also, without metadata the `dependency` prefix is unresolvable offline. Second cause: the IT
  always used `~/.m2/repository` as the tail, not the repository the build actually used.
- **InstallerIT shellcheck**: locally shellcheck is missing (expected). In CI it already ran (the old run shows only
  RealMaven's 2 skips); the standalone Shellcheck step duplicated it.
- **Jdk8JavadocParameterNamesIT** (T22, found in the CI run, not in the brief): skipped in CI because it read
  commons-lang3 3.5 + its javadoc jar from `~/.m2`, which only this laptop had (downloaded by hand in T19).

## Fixes
- `testsupport.Prerequisites` (new) — `fromEnvironment()/of(env)`, `require(met, what)`: aborts (skip) normally,
  `fail`s with "prerequisite missing in CI (CI=true), not skipping: …" when `CI=true`. Used by all three ITs (the
  "Linux only" platform check in InstallerIT stays a plain assumption). `PrerequisitesTest` 4 unit tests.
- `RealMavenResolutionIT`: Maven = `-Djdoc.mavenHome` (failsafe, from `${maven.home}`, i.e. the Maven running the
  build, also under `./mvnw`) `/bin/mvn`, else `JDOC_MVN`, else PATH. Tail repo = `-Djdoc.localRepository`
  (`${settings.localRepository}`), default `~/.m2/repository`. The temp parent POM pins, via `pluginManagement`, the
  plugins from `-Djdoc.offlinePlugins` (compiler, resources, dependency at the build's versions), which the build has
  resolved before `integration-test`; this also makes the `dependency` prefix resolve from the project offline.
  The IT stays offline.
- `pom.xml` (test config only): `maven-resources-plugin` pinned to 3.4.0 (unchanged behaviour under `./mvnw`) so the
  version is known; failsafe properties `jdoc.mavenHome`, `jdoc.localRepository`, `jdoc.offlinePlugins`,
  `jdoc.itFixtureJars`; a dependency-plugin `copy` execution in `pre-integration-test` (`it-fixture-jars`) that
  resolves commons-lang3 3.5 jar + javadoc jar into `target/it-fixture-jars`.
- `InstallerIT`: shellcheck test covers `dist/install.sh`, `dist/bin/jdoc` and `scripts/*.sh` (the same set as the
  old CI step), prerequisites via the helper.
- `build.yml`: standalone Shellcheck step removed (the Tools step still installs shellcheck before Maven; the IT
  covers the same files inside `verify`); comment on the Build step about `CI=true`.
- CI-like local check: empty temp `-Dmaven.repo.local`, `CI=true`, `-Dit.test=RealMavenResolutionIT,
  Jdk8JavadocParameterNamesIT`: both pass, 0 skipped. With `CI=true` and no shellcheck, InstallerIT fails with the
  clear message (as intended).
