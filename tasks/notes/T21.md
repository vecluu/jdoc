# T21 — Licence, NOTICE and third-party notices

## What exists now
- `NOTICE` — jdoc lines plus one carried-forward line: "This product includes software developed by David Crawshaw
  (sqlite-jdbc; see THIRD-PARTY-NOTICES)". Nothing else added.
- `THIRD-PARTY-NOTICES` (new, ~300 lines) — one `[id]` section per component: `sqlite-jdbc` (Apache-2.0 + ISC +
  BSD-2 texts, SQLite blessing/public-domain statement, extension-functions.c, Commons Lang origin of
  `org/sqlite/date`), `jsoup` (MIT), `asm` (BSD-3), `vineflower` (Apache-2.0, incl. the three nested plugin jars),
  `jetbrains-annotations`, `kotlin-metadata` (Apache-2.0), `kotlin-protobuf` (BSD-3, Google, full text),
  `slf4j-api`, `slf4j-simple` (MIT). Each has coordinates/version, URL, SPDX, jar paths and copyright lines.
- `LICENSE` unchanged.
- `src/test/java/io/github/vecluu/jdoc/LicenseNoticesIT.java` — failsafe guard on the built shaded jar, 4 tests:
  root files equal `META-INF/{LICENSE,NOTICE,THIRD-PARTY-NOTICES}` byte for byte; no other licence/notice/copying
  file at the `META-INF/` root; every jar entry (after stripping `META-INF/versions/N/`) and every entry of every
  nested jar maps via a longest-prefix allow-list to a section id that exists in THIRD-PARTY-NOTICES (nested-nested
  jars are rejected); every resolved runtime `g:a:v` from `runtime-dependencies.txt` occurs in THIRD-PARTY-NOTICES.
  Skips (assumption) only when `jdoc.projectRoot` is unset, i.e. an IDE run; fails if the jar or list is missing.

## pom.xml changes
- Metadata: `<url>`, `<inceptionYear>2026`, `<licenses>` (Apache-2.0, repo), `<developers>` (vecluu), `<scm>`.
- Shade: `ApacheLicenseResourceTransformer` + three `IncludeResourceTransformer`s from `${project.basedir}`; `*:*`
  filter also excludes `META-INF/NOTICE` and `META-INF/NOTICE.*`. Existing transformers/filters kept.
- `maven-dependency-plugin` 3.11.0 (already in the local repo) `list` execution in `package`, `includeScope=runtime`,
  output `${project.build.directory}/runtime-dependencies.txt`.
- Failsafe `systemPropertyVariables`: `jdoc.projectRoot`, `jdoc.shadedJar`, `jdoc.runtimeDependencies`.
- `maven-jar-plugin` `forceCreation=true`. Reason: on an incremental build the jar plugin considered the already
  *shaded* `jdoc.jar` up to date, shade re-shaded it and failed with "duplicate entry: META-INF/THIRD-PARTY-NOTICES"
  (before T21 this silently re-shaded a shaded jar). Costs well under a second.
