# T03 notes — index store (SQLite)

Package `io.github.vecluu.jdoc.index` (main + test). No other package contains SQL.

## Public API
- `IndexDatabase` — open/create `index.db`, WAL, `foreign_keys=ON`, `synchronous=NORMAL`, busy timeout (default 60 s),
  `PRAGMA user_version` schema check (mismatch → drop all tables, recreate). `open(CachePaths)` (creates cache root),
  `open(Path, Duration busyTimeout)`, `inTransaction(Supplier<T>)`, `runInTransaction(Runnable)` (nested calls join the
  outer transaction; rollback on any exception), `inTransaction()`, `schemaVersion()`, `close()`.
  One connection per instance: confine an instance to one thread at a time.
- `ArtifactRepository` / `JdbcArtifactRepository` — `findByKey(ArtifactKey)`, `findByJarPath(Path)` (List),
  `findByIds(ids)`, `findAll()` (by key), `save(artifact)` (deletes an existing row with the same key — cascading — then
  inserts; returns the artifact with its new id; input id ignored), `delete(id)` (cascade).
- `TypeRepository` / `JdbcTypeRepository` — `insertAll(artifactId, descriptors)` → `List<IndexedType>` with ids in
  input order (also writes each descriptor's supertypes); `findById`, `findByIds` (unscoped);
  scoped: `findByBinaryName(TypeName, scope)`, `findBySimpleName(String, scope)` (case-insensitive),
  `findByDisplayName(String, scope)` (`java.util.Map.Entry`, case-sensitive), `findByPackage`,
  `searchByName(text, scope, limit)` (case-insensitive substring of the display name/FQCN), `listNames(scope)` →
  `List<TypeRef>` (typeId, artifactId, TypeName) for camel-hump matching in Java, `listPackages(scope)` (sorted,
  distinct; default package = ""), `findWithoutSources(artifactId)`, `countByArtifact(artifactId)`.
  Returned `IndexedType`s always carry their full descriptor including direct supertypes (in order).
- `SupertypeRepository` / `JdbcSupertypeRepository` — `supertypesOf(typeId)` (ordered), `directSubtypesOf(TypeName,
  scope)` (for `impls`; direct edges only, transitive closure is the caller's job).
- `MemberRepository` / `JdbcMemberRepository` — `insertAll(Map<typeId, List<MemberDescriptor>>)` and
  `insertAll(typeId, list)` (JDBC batches of 1000, one transaction, returns row count), `membersOf(typeId)`
  (declaration = insertion order), `membersOf(Collection<typeId>)` → `Map<typeId, List>`, `findByName(name, scope)`
  (case-insensitive exact), `searchByName(text, scope, limit)` (case-insensitive substring).
- `TypeRef` — record (typeId, artifactId, TypeName).
- `IndexLock` (interface, `Lease acquire()`, `Lease extends AutoCloseable`) / `FileIndexLock(Path lockFile, Duration
  timeout)` — in-process fair `ReentrantLock` + OS `FileChannel.tryLock` polled with backoff until the timeout
  (`DEFAULT_TIMEOUT` 10 min). Reentrant per thread; closing a lease twice is harmless. Timeout/interrupt/I/O →
  `IndexException`. Use one instance per lock file per process (a second instance still works by polling).

Scope ("collection of artifact ids") is `Collection<Long>`; an empty scope returns empty results without a query.
Read results are ordered by binary name, then artifact id (members: then declaration order).

## Decisions / deviations
- Large scopes: ids are passed as one JSON-array parameter expanded with `json_each(?)`
  (`col IN (SELECT value FROM json_each(?))`); no parameter limit, no temp tables (tested with 100k ids). Internal
  `IdList`.
- Supertypes are written by `TypeRepository.insertAll` from `TypeDescriptor.supertypes()` (single source of truth),
  so `SupertypeRepository` is read-only instead of having its own batch insert.
- Transactions use `BEGIN IMMEDIATE` (write lock up front, waits via busy timeout) to avoid lock-upgrade deadlocks
  between processes.
- `artifacts.id` is `AUTOINCREMENT` so a re-indexed artifact never reuses a deleted id.
- `indexed_at` stored as ISO-8601 text (exact `Instant` round trip); `ParameterInfo` lists encoded as
  `name␟type␟erased` joined by `␞` (ASCII US/RS); offsets as nullable start/end column pairs.
- `findWithoutSources` excludes both SOURCES and JDK doc sources (both are source text).
- Substring searches use `LIKE` (wildcards escaped): case-insensitive for ASCII only.
- Extra columns: `types.display_name` (for display-name lookups), `members.position`, `supertypes.position`.

## Performance (dev machine)
20k types + 200k members in one transaction ≈ 2.3 s (types ~1.3 s: one `INSERT … RETURNING id` per row; members
~0.9 s batched); simple-name lookup ≈ 0.3 ms; member substring scan over 200k ≈ 45 ms; cascade delete ≈ 0.5 s.
