  sqlite library for the folder sqlite-jdbc itself reports (`java -cp jdoc.jar org.sqlite.util.OSInfo`), extracted

- `cli.TrainingWorkload` (new, public) — runs a workload file (one command per line, `#` comments) in one JVM, a fresh
  `JdocCli` per command; exit 3 if any command exits 3 (not found/ambiguous are fine). `forEnvironment`, `runFile`,

- `Main.run` (outside my packages, 4 lines): if system property `jdoc.aotTraining` is set, runs that workload

## Fingerprint and fallback
`lib/jdoc.aot.key` is a sh file (comments with the training java and `java -version`, then `aot_flags`, `aot_home`,
`aot_stat`), sourced by the wrapper. Match = same JVM flags and identical
`stat -L -c '%s %Y %i' jar <java on PATH> <aot_home>/release <aot_home>/lib/modules` (size, mtime seconds as the JVM
checks them, inode). One `stat` fork, no JVM launch; `stat -L` on the PATH java follows symlinks, so a different JDK
(alternatives, another PATH) mismatches even if the home path string is reused. Without GNU/busybox `stat` (macOS)
it always falls back, which is safe. Measured fallback cost ~130 ms vs ~86 ms AOT vs ~167 ms no cache (`method`).
