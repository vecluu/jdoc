# T02 notes — module and version resolution (`module`)

Status: done, `./mvnw -B -q -Djdoc.buildDir=target/T02 verify` passes. Package `io.github.vecluu.jdoc.module`.

## Entry point
- `ClasspathResolver` (interface): `ModuleClasspath resolve(Path start)`. `start` is the `--from` file or a directory,
  relative paths resolve against the working dir. Throws `ResolutionException` (→ exit 3) when there is no
  `pom.xml` above `start`, or Maven failed and nothing usable is available.
- `MavenClasspathResolver` — the implementation. Wire it with `MavenClasspathResolver.create(env)` (real process)
  or `create(env, MavenInvoker, Clock)` (tests). `@Builder` exists for full control.
  Flow: locate module → POM key → reactor → cache hit (`deps.txt` exists: RESOLVED, no Maven) → else Maven →
  success: commit deps.txt + meta.json, RESOLVED → failure: newest list for the same module dir (STALE,
  warning `warning: mvn failed, using classpath resolved at yyyy-MM-dd HH:mm` in the clock's zone) → else newest
  versions in the local repo for declared deps (UNRESOLVED, warning
  `warning: mvn failed, versions unresolved: using newest versions in the local repository`) → else exception.
  Reactor modules are always dropped. Warnings are only returned in `ModuleClasspath.warnings()`, not logged.

## Public classes (one line each)
- `ModuleLocator(workingDir)` — `locate(start)` → real path of nearest dir with a `pom.xml` file.
- `PomReader` — secure DOM read (no DOCTYPE/external entities, namespace optional) → `PomModel`; interpolates own
  `<properties>` and `project.*`/`parent.*`; throws `ResolutionException` for unreadable/malformed POMs.
- `PomModel(file, Optional<Gav> coordinates, Optional<ParentReference> parent, modules, dependencies)` —
  `directory()`, `hasCoordinates(gav)`. Modules include `<subprojects>` and profile modules.
- `ParentReference(gav, Optional<String> relativePath)` — empty = `<relativePath/>`; default `../pom.xml`;
  `localPomCandidate(dir)` (a directory means its `pom.xml`).
- `DeclaredDependency(groupId, artifactId, scope, type, classifier)` — direct `<dependencies>` only.
- `PomHierarchy(PomReader)` — `localChain(modulePom)` → `LocalPomChain(poms, repositoryParent)`,
  `localParent(pom)` (only if coordinates match the declaration), `tryRead(file)`.
- `PomKeyCalculator(hierarchy, localRepo)` — `calculate(modulePom)` → `PomKey(value, fingerprints)`;
  `PomFingerprint(file, sha256 | "mtime:<millis>" | "mtime:absent")`.
- `MavenInvoker` (interface) `run(MavenCommand)` → `MavenResult(success, exitCode, output)`, `summary()`.
- `ProcessMavenInvoker(executable, javaHome, timeout)` / `from(env)` — merged stdout+stderr captured (debug log
  only), stdin closed, `JAVA_HOME` set, killed after timeout (default 5 min).
- `MavenDependencyLister(invoker)` — the exact outline command in the module dir; on failure retries once from the

- `DepsFileParser([Predicate<Path> fileExists])` — `parse(text)`, `parseLine(line)`.
- `ModuleCache` (interface) / `FileModuleCache(CachePaths, ModuleMetaCodec)` — `readDependencyList(key)`,

  Optional). JSON via package-private `FlatJson` (strings/numbers only).

## Decisions / deviations
- POM key also hashes the module directory path (and each POM's path), so two checkouts with identical POMs never
  share a `modules/<key>/` dir and `meta.json` maps 1:1 to a module path. The key still only changes when a POM
  changes (or the module moves).
- Maven writes to `modules/<key>/deps.txt.<uuid>.tmp`, renamed to `deps.txt` only on success: a `deps.txt` always
  means "Maven succeeded for this key", and concurrent jdoc processes never see partial files. Failed runs leave
  nothing behind, so the next call retries Maven.
- `-pl ... -am` retry: with `-am` every reactor module writes the same `-DoutputFile`; the target module runs last,
  so the file ends up holding its list.
- Reactor detection goes up through aggregators (parent dir POM listing this dir) and local parents, then down
  through `<modules>`/`<subprojects>`/profile modules. Matching is by `groupId:artifactId` (any version).
- UNRESOLVED guess uses deps declared in the module POM and its local parents (not repo parents/BOMs), skips
  non-jar types, system scope and `${...}` leftovers. "Nothing usable" = guess empty while at least one jar dep was
  declared; a module declaring no deps gets an empty UNRESOLVED classpath (JDK-only lookups still work).
- Maven is not passed `-Dmaven.repo.local`: the exact outline command is kept, so a custom `JDOC_M2_REPO` only
  affects the fallback guess and SNAPSHOT-parent mtime, not Maven itself (follow-up if that matters).
- Cache hits do not re-check that listed jars still exist beyond the parser skipping missing ones.

## Known gaps / follow-ups
- Old `modules/<key>/` dirs are never pruned (they are small; they also serve as STALE fallbacks).
- Version comparator is a simplification of Maven's (no list nesting semantics for `-` vs `.`).
