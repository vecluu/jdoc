# T04 notes — Java source parsing and doc-comment rendering

Status: done. `./mvnw -B -q -Djdoc.buildDir=target/T04 verify` passes.

## Public API

### `source`
- `JavaSourceParser` (AutoCloseable, not thread-safe; one per thread/indexing run) — javac `JavacTask.parse()` only,
  one compiler + file manager reused. `parse(JavaSource)` / `parse(JavaSource, KnownTypes)` → `ParsedSourceFile`.
  Syntax errors do not throw (listed in `problems()`); javac internal failures → `SourceParseException`.
- `JavaSource(path, text, docSource)` — path must end in `.java` (file name matters for package-/module-info);
  docSource SOURCES, JDK or DECOMPILED (JAVADOC rejected).
- `KnownTypes` — `contains(TypeName)`; `none()`, `of(collection)`. Pass the sources jar's / src.zip's type list so
  same-package and on-demand-import names resolve exactly.
- `ParsedSourceFile(path, packageName, Optional packageDoc, Optional packageDocRange, types, problems)` —
  `type(TypeName)`, `hasProblems()`. module-info → no types.
- `ParsedType(descriptor, doc, members)` — `name()`, `membersNamed(name)`. Outer types before nested ones.
- `ParsedMember(descriptor, doc, implicit)` — full `RenderedDoc` for `jdoc method`; `implicit` = compiler-generated.
- `MemberSourceSlicer` — `member(text, md)`, `docComment(text, md)`, `declaration(text, md)` (without doc),
  `slice(text, range)`; all re-indented (first-line indentation restored, common indent removed).

### `javadoc` (doc-comment side)
- `DocCommentRenderer` — `render(DocCommentTree)` → `RenderedDoc` (`null` → `RenderedDoc.missing()`),
  `hasDeprecatedTag(tree)`, `parameterDescriptions(tree)` (record components). Package-private helper `DocCommentHtml`
  turns inline tags into HTML, then T01's `HtmlTextFormatter` / `FirstSentenceExtractor` / `BlockTagFormatter` apply.

## Rules implemented (for T05/T08/T09 alignment)
- **All members and types of every visibility** are returned (private/package too); filter with
  `visibility().isApi()`. Local and anonymous classes (incl. enum constant bodies) are skipped.
- Signatures exactly per architecture; only `protected` shown as access. Interface methods without body get
  `abstract`, interface fields `static final`, annotation elements `abstract T name()` (no default value). T05 does
  the same. `final`/`synchronized`/`native` on methods are not shown.
- Class-type names are rendered via the resolver's `relativeName()`, so a written `Entry` that resolves to
  `Shapes$Registry$Entry` renders as `Shapes.Registry.Entry` (matches bytecode rendering); fully qualified names
  lose their package; annotations dropped; type args joined with `", "`. `ParameterInfo.erasedType` uses the same
  (`Map.Entry`, `Object[]` for `T...`, first bound for type variables, recursive).
- Varargs detected from the text between the element type and the parameter end (Tree API hides the flag).
- Implicit members (flag `implicit`, no ranges): default constructor (class access), enum `values()`/`valueOf(String name)`,
  record canonical constructor (record access) and accessors, each only if not declared; docs mimic javadoc's
  generated text, accessors use the record's `@param` text. Record `equals/hashCode/toString` are NOT added
  (bytecode has them; T05 may list them — reconcile in T08 if needed). Record component fields are not emitted.
- Enum constructors are PRIVATE. Nested enum/record/interface/annotation and types in interfaces are `static`.
- Type modifiers: visibility, `abstract` (classes), `static`, then explicit `final sealed non-sealed strictfp`.
  `non-sealed` cannot be seen in bytecode (only difference to T05 known to me).
- Supertypes: superclass first (implicit `Object`/`Enum`/`Record`; none for interfaces and `java.lang.Object`),
  then interfaces; annotations get `java.lang.annotation.Annotation`. Resolution order: same-file types (innermost
  scope outwards), single-type imports, same package (if `KnownTypes` confirms), `java.lang` (built-in JDK 25 list or
  `KnownTypes`), on-demand imports confirmed by `KnownTypes`, else guess = first on-demand import, else same package.
  Names with a lowercase first segment are fully qualified (package ends at first uppercase segment). Inherited
  member types are not resolved.
- Ranges: member/type range = doc comment start (if documented) through end of body/`;`; `docRange` = `/** ... */`.
  `TypeDescriptor.declarationRange` also includes the doc comment (same convention as members).
- Entry path: source path for SOURCES/JDK, `TypeName.classEntryPath()` for DECOMPILED.
- Doc rendering: `{@link}`/`{@linkplain}` render the reference **as written** (`#radius()` keeps the `#`), label if
  given; label text is plain (shared formatter: links never get backticks). `{@value X}` → `X` (no constant value);
  `{@snippet}` inline body → `<pre>`; inline `{@return x}` → "Returns x." plus `@return x` if no block `@return`;
  `{@summary}` defines the first sentence; `{@systemProperty}` → backticks; `{@index}` → term; `{@docRoot}` dropped.
  Block tags kept: param (`<T>` for type params), return, throws/exception (as `@throws`, type as written), since,
  deprecated, see (references as written), apiNote/implNote/implSpec; others (author, version, serial, jls, spec…)
  dropped. `inheritsDoc` = comment missing or `{@inheritDoc}` anywhere (a comment with only block tags is not
  flagged).

## Deviations
- `source` depends on `error` (for `SourceParseException`); the architecture table lists only `model`, `javadoc`.
- `DocCommentRenderer`/`source` use `jdk.compiler` (`com.sun.source.*`), as the architecture intends.

## Changes outside my packages
None (T01's shared formatter used unchanged).

## Performance
java.base from `src.zip`: 3407 files, 6761 types, 80663 members in ~8 s on one thread (cold). ~4 s of that is raw
javac parsing; doc rendering is ~0.5 s. T08 can parallelise with one parser per thread.
