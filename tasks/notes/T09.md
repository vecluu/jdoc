# T09 notes — lookup services (read side)

Status: done. `./mvnw -B -q -Djdoc.buildDir=target/T09 verify` passes (whole tree: 713 unit, 88 IT).
Package `io.github.vecluu.jdoc.lookup`. All results are values; nothing is formatted. Services keep small
per-call caches and are not thread-safe (one set per call).

## Public API
- `LookupScope(List<ScopedArtifact>, ResolutionStatus)` — artifacts in **classpath order** (decides shadowing);
  `of(list)`, `artifactIds()`, `artifact(id)`, `rank(id)`, `versionUnresolved()`. `ScopedArtifact(id, ArtifactKey)`
  + `label()`. T10 builds it from T08's `IndexedClasspath` (put the JDK where javac would: first).
- `LocatedType(IndexedType, ScopedArtifact)` — `name()`, `descriptor()`, `id()`, `label()`.
- `LookupServices.create(artifactRepo, typeRepo, supertypeRepo, memberRepo, JarEntryReader, JavadocDocs,
  DecompiledSourceProvider)` — wires everything; record accessors per service; `close()` closes the lazy javac parser.
- `ScopedTypes` — scoped type reads in classpath order (`byBinaryName`, `first`, `locate`), `isApiVisible` (public/
  protected with API-visible enclosing chain), static `firstPerName`, `byDisplayName`.
- `TypeResolver.resolve(text|TypeReference, scope)` → `TypeLookup`: `Found(input, type, shadowed)`,
  `NotFound(input, suggestions)` (case-insensitive simple-name matches), `Ambiguous(input, candidates)` (by display
  name), `Invalid(input, message)`. Exact (FQCN/binary) candidates first, then package-less ones.
- `TypeHierarchy` — `directSupertypes`, `supertypes` (javadoc order: superclass chain, interfaces BFS, `Object`
  last; unknown kept by name as `Supertype(name, Optional.empty())`), `subtypes` → `Subtype(type, direct)` (transitive,
  across artifacts, walks through non-API types without listing them).
- `OverrideMatcher.overrides(sub, sup)` — name + erased params; a supertype param declared as a bare type variable
  matches anything; fields hide by name; constructors never.
- `TypeMembers` — `declared(type)` (API, declaration order), `inherited(type, scope)` → `MemberMatch`es (no ctors, no
  static interface methods, nothing overridden/hidden by a closer type).
- `ClassViewService.view(type, scope)` → `ClassView(type, directSupertypes, firstParagraph, members, nestedTypes,
  inherited: List<InheritedMembers(declaringType, names)>)`. Member order: enum constants, fields, constructors,
  methods (javadoc summary order), declaration order within. Includes direct API nested types.
- `MemberLookupService.lookup(text|MemberReference, scope)` → `MemberLookup`: `Found(type, members)`,
  `MemberNotFound(type, reference, suggestions)` (same-name overloads, else NamePattern-similar names),
  `TypeNotResolved(typeLookup)`, `Invalid`. Own members first; inherited only if no own match.
- `MemberMatch(member, declaringType, inherited)` + `reference()` (`a.B#m(int)`).
- `DocLoader` — `typeDoc(type)`, `memberDoc(match, scope)` → `MemberDoc(doc, inheritedFrom)`, `ownMemberDoc`,
  `packageDoc(pkg, typesInPackage)` → `PackageDoc(doc, artifact)`.
- `SourceLoader.source(match, scope)` → `MemberSource.Available(member, code, doc, decompiled)` |
  `Unavailable(member, reason)`.
- `FindService.find(pattern, scope)` → `FindResult(pattern, hits, truncated)`; `FindHit(reference, type, member,
  score)`; `MAX_HITS` = 200.
- `MemberSearchService.search(name, scope)` → `List<MemberMatch>`.
- `PackageService.describe(pkg, scope)` → `PackageLookup.Found(PackageView(name, doc, types))` | `NotFound(name,
  suggestions)`.
- Boundaries: `JarEntryReader` / `ZipJarEntryReader` (zip text entries), `JavadocDocs` / `JarJavadocDocs` (T05 reader,
  page cache), `ArtifactFiles` (artifact rows by id, cached), `SourceFiles` (+ `ParsedText`; text+parse cache, lazy
  `JavaSourceParser`).

## Decisions
- Shadowed duplicates (same FQCN later on the classpath) are reported in `Found.shadowed`, logged at debug.
- Doc inheritance (`DocInheritance`, package-private): only instance methods; walk supertypes in hierarchy order;
  missing doc → whole inherited doc (incl. `@throws`); `{@inheritDoc}` → inherited description **prepended** (the
  rendered text no longer shows the tag position; it is almost always first) and inherited first sentence; missing
  `@param`/`@return`/`@throws` filled in. DECOMPILED types never get docs (also not inherited ones).
- Members are located in a re-parsed source by stored start offset, else kind + `erasedKey()`; decompiled text by
  kind + erasedKey, else unique name + arity.
- `source` for JAVADOC types: decompiled body plus the rendered page doc in `Available.doc`; for SOURCES/JDK the code
  already starts with the Javadoc comment. Implicit members, decompiler failures (`DecompilationException`) and JDK
  types without `src.zip` are `Unavailable` values; other `JdocException`s (unreadable jars) propagate.
- Package docs: `package-info.java` from the sources jar / `src.zip` (module prefix derived from a type's entry path),
  else javadoc `package-summary.html`; first artifact in classpath order that has one.
- `find`: a pattern with `.` matches types' display names and skips members.

## Changes outside my packages
- `query.NamePattern` (sanctioned): camel humps only if the pattern has an upper-case letter (`usesCamelHumps()`
  added); all-lower-case patterns are exact/prefix/substring. `NamePatternTest` updated (lower-case hump cases moved
  to non-matches, ordering test now substring-only, new `readsPatternsAsCamelHumpsOnlyWithAnUpperCaseLetter`).

## Known gaps / follow-ups
- `find` members: candidates come from `MemberRepository.searchByName` (substring), so a camel-hump pattern finds a
  member only if it is also a substring (`gFB` does not find `getFooBar`). Fix would need a T03 method listing
  distinct member names in scope.
- Override detection is heuristic (no attribution): a generic supertype parameter like `List<T>` vs `List<String>`
  matches through erasure; `T` declared with a bound matches anything in that position.
