# T15 notes — rendered docs stored in the index; no javac/jsoup on the lookup hot path

Status: done. `./mvnw -B -Djdoc.buildDir=target/T15 verify` passes (whole tree: 856 unit, 119 IT, 0 skipped).

## API (new / changed)
- `index.DocRepository` / `JdbcDocRepository(db)`: `insertTypeDocs(Map<typeId, RenderedDoc>)`,
  `insertMemberDocs(Map<typeId, List<RenderedDoc>>)` (aligned by position with `MemberRepository.insertAll`),
  `savePackageDoc(artifactId, pkg, doc)`, `typeDoc(id)`, `memberDoc(id)`, `packageDoc(artifactId, pkg)`, all
  `Optional`. `RenderedDoc.missing()` is never stored (absence = no doc). Batches are encoded in parallel.
- `index.DocCodec` (package-private): flag byte (inheritsDoc / deflated / first sentence is a prefix of the
  description → only its length is stored) + varint-length UTF-8 strings; raw deflate when the body is >= 160 bytes
  and gets smaller. Corrupt blobs → `IndexException`.
- `Schema.VERSION` 2 → **3**: `type_docs(type_id PK)`, `member_docs(member_id PK)`, `package_docs(artifact_id,
  package)`, all `ON DELETE CASCADE`. Separate tables so `find`/`member` scans of `types`/`members` stay small.
- `JdbcTypeRepository.insertAll` now assigns explicit ids (`max(id)+1…`, inside the write transaction) and batches,
  instead of one `INSERT … RETURNING id` query per row (it was the slowest part of the writer thread).
- `indexer.TypeEntry(type, doc, List<MemberEntry>)` (+ `undocumented(type, members)`, `memberDescriptors()`,
  `memberDocs()`), new `MemberEntry(descriptor, doc)`. `EntryProducer.produce(EntrySink)`; new `EntrySink`
  (`types(batch)`, `packageDoc(pkg, doc)`). `SqliteIndexStore` takes a 6th argument (`DocRepository`).
- `TypeDocResolver`: SOURCES keeps `ParsedType.doc()`/`ParsedMember.doc()`, JAVADOC keeps the page's type and member
  docs, DECOMPILED stores none; `packageDoc(pkg)` = non-empty `package-info.java` of the sources jar, else
  `package-summary.html`. `JarArtifactIndexer` stores a package doc per package of the jar.
  `JdkSourceZipProducer` also parses `package-info.java` of indexed packages. `JrtBytecodeProducer`: no docs.
- `lookup.DocLoader(DocRepository, TypeHierarchy, MemberRepository, OverrideMatcher)` reads stored docs;
  `ownMemberDoc(LocatedType, IndexedMember)` (was `MemberDescriptor`); inheritance (`DocInheritance`) unchanged but runs
  over stored docs, across artifacts. `packageDoc` = first artifact (types' order) with a stored package doc.
- `LookupServices.create(artifacts, types, supertypes, members, DocRepository, JarEntryReader, decompiled)`.
  **Removed** `JavadocDocs`, `JarJavadocDocs` (and test `FakeJavadocDocs`): nothing reads javadoc pages at lookup time.
  `SourceLoader` (only `jdoc source`) still re-parses / decompiles, unchanged behaviour.

## Decisions
- Spec reversal recorded in `docs/ARCHITECTURE.md` (Database, Runtime flow, `lookup` row).
- No same-artifact `{@inheritDoc}` pre-resolution: lookup-time resolution over stored docs is cheap (a few row reads).
- A doc equal to `RenderedDoc.missing()` (e.g. a lone `{@inheritDoc}`) is not stored; reading it back as missing is
  equivalent, and inheritance fills it as before.
- Page size stays 4096 and compression is on (measured on the JDK index, VACUUMed copies): no compression 44.0 MB,
  deflate ≥160 B 31.3 MB, ≥64 B 31.0, level 9 31.4, 8 KiB pages 30.8, 16 KiB pages 30.7. Docs without the rest of
  the index: 22.6 MB raw text → ~13.5 MB of pages.
- Lazy wiring (`cli/CompositionRoot`): jar and JDK indexers are memoized suppliers behind `ArtifactIndexer`/`JdkIndexer`
  lambdas, created only when something must be indexed. Vineflower and the lookup javac parser are behind lambdas /
  an anonymous class (a constructor reference or a lambda returning the concrete type loads that class eagerly).
