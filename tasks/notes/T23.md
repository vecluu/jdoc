## Files
- `cli.TrainingLibrary` (new, public, has `main`) — writes the training library with the JDK's `JavaCompiler` and
  `DocumentationTool` into a Maven layout `<repo>/jdoc/training/training-{sources,javadoc,binary}/1.0/` (binary jar +
  sources jar / javadoc jar / nothing, plus a minimal POM), sorted entries and fixed timestamps; scratch dir removed.
  `withSystemTools()` (empty without compiler/javadoc), `writeTo(repo)` → `List<Artifact>`, `dependencyList(...)`
  (the `dependency:list` text), `main <repository> <dependency-list>` → exit 0 / 3 with one stderr line.
  Nested `Flavour` (artifactId, packageName) and record `Artifact`.
- `cli.TrainingLibrarySources` (package-private) — the Java sources as text blocks, one copy per package:
  interface with default/static/generic methods, class with overloads, varargs, `{@inheritDoc}`, `@Deprecated`,
  nested builder, record with compact constructor, enum with a constant body, annotation, package-info.
- `dist/install.sh` — before the recording run: `java $jvm_flags -cp jdoc.jar ...TrainingLibrary "$work/m2"
  "$work/library/deps.list"` (own JVM, so javac/javadoc are not recorded); a second module `$work/library` with a POM
  declaring the three; the fake `mvn` copies `deps.list` from the module dir if present. The workload is the old JDK
  workload + `library_workload` (22 calls with `--from ../library`: class/method/find/member/package/impls on all
  flavours, `source` on sources, javadoc and binary (Vineflower), `index`). Generation failure → warning, JDK-only
  training. Final line now says `trained on the JDK and the training library` (or `the JDK`).
- `scripts/bench-startup.sh` (T16's file) — new "first call after adding a dependency" scenarios, on by default
  (`BENCH_NEW_DEP=0` skips; skipped automatically without javac/javadoc/jar): a different library (`bench.fresh`),
  new version + jars + POM change before every run; rows `new-dep sources|javadoc|binary`. The measuring loop moved
  into a `measure` function; fake mvn copies `deps.list`.

## Decisions
- The generator is jdoc's own code in `jdoc.jar` (`io/github/vecluu/jdoc/**`), so `LicenseNoticesIT` maps it to jdoc:
  green, no change. No checked-in binaries; the javadoc jar is real JDK javadoc output (~4.5 MB uncompressed).
- The bench library is deliberately not the training library (same code paths, different names) to avoid measuring
  a library the cache was trained on.
- Kept the decompile part of the workload despite the warm-lookup cost: it is the largest gain.
