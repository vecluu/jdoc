## Changes (all output byte-identical on the commands checked: find/class/member/source incl. overloads, ctors,
fields, enum constants, nested types)
- `index.IndexDatabase.openInBackground(CachePaths)`: opens on a daemon thread; `connection()` waits on first use and
  rethrows the open's exception; `close()` waits and ignores an open failure. Logger looked up lazily (a static
  `@Slf4j` field initialised slf4j, ~12 ms, before the thread could start). `CompositionRoot` starts it first.
- `module` POM fast path (T02 design kept; parsing classes unchanged in behaviour):
  - `PomFiles` (interface: isRegularFile/isDirectory/read/lastModifiedTime), `NioPomFiles`, `RecordingPomFiles`
    (`record(work)` → value + every path touched). `PomHierarchy(reader, files)` is the single file gateway (`files()`,
    `read(path)`); `ReactorDetector`, `PomKeyCalculator`, `ParentReference.localPomCandidate(dir, isDirectory)` use it.
  - `PomAnalyzer` / `PomAnalysis(key, reactor)`; `ParsingPomAnalyzer` (key calculator + reactor detector);
    `SnapshotPomAnalyzer(parsing, recordingFiles, store, stamper, localRepo, clock)`: reuses a stored analysis while
    every recorded path has the same `PathStamp`, else parses (recorded) and stores.
  - `PathStamp`/`PathStamper`/`NioPathStamper`: absent | dir | `file:size:mtimeNs:ctimeNs:dev:ino` (unix view; basic
    attributes + fileKey elsewhere). ctime catches same-size edits with a restored mtime.
  - Racy-timestamp guard: an analysis is stored only if every stamped file last changed ≥ 2 s (`SETTLE_TIME`) before
    now, so an edit in the same timestamp tick cannot keep a stale snapshot.
  - `ModuleSnapshot`, `ModuleSnapshotCodec` (tab-separated lines, `FORMAT_VERSION` 1: bump when key/reactor logic
    changes), `ModuleSnapshotStore` / `FileModuleSnapshotStore` (`<cache>/module-snapshots/<fnv64>.txt`, atomic
    rename; I/O problems only cost a parse; no MessageDigest because its provider set-up costs ~9 ms).
  - `PomReader` creates its `DocumentBuilderFactory` on first parse; new `read(Path, byte[])`.
  - `MavenClasspathResolver`: builder fields `keyCalculator` + `reactorDetector` replaced by `analyzer`.
- `index`: `TypeRepository.findNested(outer, ids)` (binary-name range `> outer$`, `< outer%`);
  `TypeRepository.listNames(ids, NameColumn, subsequence)` (LIKE prefilter, like T12's member names);
  `JdbcMemberRepository.findByNames` uses `m.name COLLATE NOCASE IN (...) AND m.name IN (...)` so the NOCASE
  `members_name` index is used (was a scan of all members in scope, 12 ms → 0.3 ms).
- `lookup`: `FindService` uses the prefiltered type names; `ClassViewService.nestedTypes` uses `findNested`;
  `SourceLoader` cuts SOURCES/JDK members by stored offsets when `storedRangeMatches` (range in text, doc range starts
  with `/**`, declaration names the member as a whole identifier), else parses as before; `SourceFiles.text()`.

## Decisions / deviations
- Spec-level: new cache dir `module-snapshots/` (OUTLINE cache layout should list it); `jdoc source` of an unchanged
  source entry no longer parses (ARCHITECTURE runtime flow updated). Superset caveat of the type prefilter is the same
  as T12's: SQLite `LIKE` folds ASCII only, so a name whose non-ASCII char lower-cases to ASCII (U+0130, U+212A) could
  be missed; no Java type names are known to use them.
- Not done (measured too small or T17's job): slf4j init on its own thread (−5 ms), `slf4j.provider` property (−3 ms,
  prints an info line), sqlite native-library pre-extraction (−70 ms, belongs to T17's wrapper),
  `SQLiteConfig`'s `FastDateFormat`/CLDR (~25 ms, inside sqlite-jdbc; overlapped by the background open).
