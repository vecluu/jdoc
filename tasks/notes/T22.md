## Public API (new / changed)
- `javadoc.JavadocParameter(type, name)`: one parameter as shown on a javadoc page.
- `javadoc.JavadocMemberDoc(anchors, doc, Optional<List<JavadocParameter>> parameters)`. The old 2-arg constructor is
  kept and gives empty parameters.
- `javadoc.JavadocTypePage.parameterNames(MemberDescriptor) → Optional<List<String>>`. It only uses the section whose
  anchor matches exactly (`JavadocAnchor.matches`, never the loose name+arity match). The arity must be equal and every
  shown type must agree with the member's declared or erased type (`simpleForm`: no generics, no packages, `...`=`[]`).
  Otherwise the result is empty.
- `javadoc.SignatureParameterParser` (package-private) reads the parameter list from the signature text. Layouts:
  JDK 17+ `div.member-signature`, JDK 13–16 `div.memberSignature`, JDK 11 `pre.methodSignature` (zero-width space),
  JDK 8 first `<pre>` of the `li`. It skips annotations before the member, including ones with `(...)` and quoted
  parens. It also strips type-use annotations, `final` and receiver parameters. Anything unreadable means unknown.
- `indexer.ParameterNames.apply(member, names)` (package-private) renames the `ParameterInfo`s and rewrites
  `name(<old list>)` in the stored signature. It keeps the member unchanged when the count differs, a name is not an
  identifier, names repeat, or the old list is not found. `TypeDocResolver.fromJavadoc` applies it.
- `lookup.ScopedArtifact.isJdk()`, `lookup.FindHit.fromJdk()`.
- `index.Schema.VERSION` 3 → **4** (tables unchanged; stored signatures changed, so old indexes are rebuilt. Checked:
  a v3 cache is rebuilt and then shows the new names).

## Behaviour
- **find**: sort is score, then library before JDK, then types before members, then reference. The type pre-sort
  (before the 200 cap) uses the same tie-break. As the brief says, library *members* with an equal score also rank above
  JDK types, so `org.jsoup.parser.StreamParser#document()` now comes before `javax.swing.text.Document`.
- **member**: library matches come first, then JDK. Each group keeps the old order (type name, then declaration).
- **Interfaces**: `abstract` is never rendered on interface or annotation methods, even when written in the source.
  `static final` is never rendered on interface or annotation fields (`isStatic` stays true). `default` and `static`
  methods keep their keyword, and abstract classes keep `abstract`. Source (T04) and bytecode (T05) both do this.
  `docs/ARCHITECTURE.md` "Rendered signature format" is updated.
- Spec-level for OUTLINE (I did not edit it): the find/member tie-break above. Open question "Old javadoc jars" is now
  answered: names are taken from the HTML.
