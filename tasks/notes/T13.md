# T13 notes — remember jars that fail to index

Status: done. My tests pass; whole-tree `verify` currently fails only in other agents' in-progress work (see Tests).

## Public API
### index (`io.github.vecluu.jdoc.index`)
- `FailedArtifact` — record (key, jarPath, jarMtime, jarSize, reason): one row of `failed_artifacts`; reason is
  collapsed to one line (blank → `unknown error`); `matches(path, mtime, size)`.
- `FailedArtifactRepository` / `JdbcFailedArtifactRepository(IndexDatabase)` — `find(ArtifactKey)`,
  `save(failure)` (INSERT OR REPLACE, one row per artifact), `delete(ArtifactKey)` → boolean.
- `Schema.VERSION` 1 → **2**: new table `failed_artifacts(artifact_key PK, jar_path, jar_mtime, jar_size, reason)
  WITHOUT ROWID`. Existing `index.db` files are dropped and rebuilt on first open (existing behaviour).

### indexer (`io.github.vecluu.jdoc.indexer`)
- `IndexFailure` — record (artifact, reason, previouslyFailed). `IndexReport.failures()` is now
  `List<IndexFailure>` (was `List<String>`), so the formatter decides the wording.
- `IndexStore` gains `findFailure(key)`, `recordFailure(FailedArtifact)`; `replace(...)` now also forgets the
  artifact's failure in the same transaction. `SqliteIndexStore` takes a 5th constructor argument
  (`FailedArtifactRepository`).
- `ClasspathIndexer`: a pending target (new/changed/forced) that is not forced and whose remembered failure matches
  its current path+mtime+size is skipped **before** the lock (no lock if nothing else is pending) and reported as
  `IndexFailure(previouslyFailed=true)`; an older index of it stays in scope. The check is repeated after acquiring
  the lock (another process may have recorded the failure while we waited). On a fresh failure the indexer records
  it (a store error while recording only logs a warn). Changed jar → retried; `force` (Maven artifacts) /
  `forceJdk` (JDK) → retried; success → failure forgotten.

## Decisions
- Keyed by artifact key (primary key) with jar path/mtime/size stored and compared, rather than by jar path: it
  matches `IndexStore.find(key)` and covers the JDK the same way. A failure of a different jar state (moved jar,
  other mtime/size) is ignored and overwritten.
- Failure rows are independent of `artifacts` (no FK): an artifact may fail without ever having been indexed.
- Skipped jars still log one `warn` per call ("skipping X: it failed to index before (reason); retried when its file
  changes or on a forced index"), since lookup commands do not print `report.failures()` and the user should know
  the artifact is missing from scope.
- `jdoc index` output (app/IndexCommand): `  <label>: <reason>`; previously failed adds
  `  (previously failed; retried when the jar changes or with --force)`.
