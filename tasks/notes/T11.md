# T11 notes — hide unusable inherited protected members

Status: done. `./mvnw -B -q -Djdoc.buildDir=target/T11 verify` passes (whole tree at the time, including the
in-progress T12–T14 work: 838 unit, 106 IT, 0 failures).

## API changes (`lookup`)
- `TypeMembers.inherited(type, scope)` now leaves out inherited **protected** members when the type cannot be
  subclassed. The override/hiding pass still runs over all inherited members first. So a protected member that a
  closer supertype hides still hides the more distant one, and a public override (e.g. `public Object clone()`)
  stays visible.
- `TypeMembers.inheritedForSubclassesOnly(type, scope)` (new) returns the protected members left out above. It is
  empty for subclassable types.
- `TypeMembers.canBeSubclassed(type)` (package-private, static) is false for `ENUM`, `RECORD` and for classes whose
  `modifiers` contain the word `final` or `sealed`. `non-sealed` does not count. Interfaces and annotations return
  true (they never inherit protected members).
- `MemberLookup.MemberNotFound` has a new 4th component `protectedInherited`: hidden protected inherited members
  that match the reference. A 3-argument constructor is kept for compatibility. `MemberLookupService` fills it on
  the not-found path (never for constructor references). Suggestions still come only from usable members.

## Decisions
- **Sealed classes are treated like final ones** (not in the task text). Users cannot subclass them. A
  `non-sealed` permitted subclass is subclassable and shows the protected members again (tested).
- **Static protected members are hidden too** (e.g. `AbstractShape.checkFactor` on the final sample `Circle`). Only
  a subclass (or the library's own package) can call them.
- Same-package access to protected members is ignored: users are not in the library's packages.
- **`finalize` stays visible on non-final classes.** It is protected, so the final/enum/record rule hides it on
  those types. Elsewhere it is still callable/overridable. The `deprecated` flag is in the index and shown by
  `jdoc method`. Keeping the class view a plain name list matches the outline.
- Own declared protected members are unaffected (`declared()` did not change).
