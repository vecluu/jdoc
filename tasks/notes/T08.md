## Public API (`io.github.vecluu.jdoc.indexer`)
- `ClasspathIndexer(store, artifactIndexer, jdkIndexer, JdkInfo, IndexLock, FileStatter, DecompiledCacheEvictor)` —
  **T10 entry point**: `index(ModuleClasspath, IndexOptions) → IndexResult(IndexedClasspath, IndexReport)`.
  Confine to one thread (it uses one `IndexDatabase`).
- `IndexOptions(force, forceJdk, reportMissingSources)` — `lookup()` (lazy, no report), `indexCommand(force)`.
- `IndexedClasspath(artifactIds, artifacts: id→ArtifactKey, jdkArtifactId, status, warnings)` — `key(id)`, `label(id)`.
  Ids in classpath order, JDK last. Scope for every T09 query.
- `IndexReport(artifactsIndexed, artifactsReused, typesIndexed, membersIndexed, missingSources, failures)` (counts
  include the JDK); `ArtifactWithoutSources(artifact, types)`, `TypeWithoutSources(name, docSource)`.
- `ArtifactIndexer` / `JarArtifactIndexer(BinaryJarScanner, DocJarLocator, ArchiveOpener, JavadocPageParser,
  Supplier<JavaSourceParser>, IndexStore, Clock)` — `index(gav, jar, FileStamp) → StoredArtifact`.
- `JdkIndexer` / `DefaultJdkIndexer(store, parsers, ClassFileReader, JdkPackageFilter, threads, clock)` —
  `index(JdkInfo, FileStamp)`, `indexedFile(jdk)` (src.zip, else `lib/modules`); `defaultThreads()` (cores, max 8).
- `IndexStore` / `SqliteIndexStore(db, artifacts, types, members)` — `find(key)`, `replace(artifact, EntryProducer)`
  (one transaction, batches), `typesWithoutSources(id)`. `EntryProducer`, `TypeEntry(type, members)`, `StoredArtifact`.
- Boundaries: `FileStatter`/`NioFileStatter` + `FileStamp`; `DocJarLocator`/`SiblingDocJarLocator` + `DocJars`;
  `ArchiveOpener`/`ZipArchiveOpener`, `SourceArchive`, `JavadocArchive`; `DecompiledCacheEvictor`/
  `DecompiledDirectoryEvictor(CachePaths)`; `JdkPackageFilter` (+ static `unqualifiedExports(moduleInfoSource)`).
- Package-private: `TypeDocResolver` (per-type fallback), `SourceFiles`, `JdkSourceZipProducer`, `JrtBytecodeProducer`.

## Behaviour / decisions
- Per-type fallback: sources file looked up per top-level type (nested follow it); a type absent from the parsed file
  falls through alone; javadoc tier = the type has its own HTML page; else DECOMPILED. `.kt`/`.scala` never count.
- Supertypes for jar artifacts always from bytecode (orchestrator decision 1). JDK: `KnownTypes` = every `.java` of
  src.zip (all modules), so supertypes resolve exactly.
- Types: everything the scanner returns (incl. package-private/private nested); members: `isApi()` only.
- Doc jars: `<jar stem>-sources.jar` / `-javadoc.jar` in the same dir (file-name based, works for timestamped
  snapshots). Classifier jars only use their own classified doc jars, never the main artifact's.
- Refresh: re-index when jar path, mtime or size differs; `force` = all Maven artifacts, not the JDK (`forceJdk`).
  Lock taken only if something is pending; re-checked after acquiring. Re-indexing an existing Maven artifact deletes
  its `decompiled/<g>/<a>/<v>/` dir (T06 note).
- Missing jars: skipped (debug). Jar that fails to index (`JdocException`): warn + `report.failures()`, older index
  kept in scope if any; the call never fails. Missing JDK file: warn, no JDK in scope.
- `IndexReport.missingSources` only when `reportMissingSources` (avoids one query per artifact on every lookup);
  lists API types only, JDK excluded.
- JDK packages: `java.*`/`javax.*`/`jdk.*`, no `internal` segment, and unconditionally exported by its module
  (`module-info.java` regex; `module-info.class` via `ModuleDescriptor` for jrt). Entry paths
  `java.base/java/util/Optional.java`. Parallel parsing: fixed pool, one parser per worker, bounded queue, the
  calling thread is the single DB writer (one transaction).
- No src.zip → `jrt:/` of that java home (`java.home` env), bytecode only, DECOMPILED, one warning.

## Known issues / follow-ups
- **T03:** opening a *fresh* `index.db` from several connections at once fails with `SQLITE_BUSY` in
  `IndexDatabase.open` (schema init/WAL switch ignores the busy timeout). Reproduced with 4 threads. Two jdoc
  processes on a first run could hit it. `ClasspathIndexerIT` opens its sessions sequentially to avoid it.
- A jar that keeps failing is retried (under the lock) on every call.
